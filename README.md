# TaskFlow

**Меньше хаоса. Больше жизни.**

Небольшое самостоятельное приложение для управления задачами: без регистрации, серверной части, сборки и обязательных внешних сервисов. Русскоязычный интерфейс на основе [дизайн-системы Superr из Refero Styles](https://styles.refero.design/style/cfd0fec1-f25a-4b9b-9bd0-d5b66960f2f2): кремовая бумага, тёмные контуры, округлые заголовки и оранжевые рукописные пометки.

## Дизайн

Из готового блока CSS Variables перенесены основные цветовые токены, скругления и тени. Композиция адаптирована под планер: слева крупный строчный заголовок, справа — настоящий рабочий список в оформлении блокнота с переплётом. На телефоне блоки выстраиваются друг под другом. Фотографию чужого товара заменяет рабочий интерфейс, а не изображение или макет. Все кнопки выполняют реальные действия.

Сохранены принципы референса: контурные кнопки на кремовой поверхности, оранжевая полоса подвала, рукописные аннотации и декоративная синяя наклейка. Для читаемости мелкие оранжевые подписи затемнены; яркий Marker Orange используется в декоре. Вместо недоступного в комплекте Gelica подключён локальный Nunito с кириллицей, для пометок — Caveat. Шрифты распространяются по SIL Open Font License; исходные лицензии находятся в `assets/fonts/`. Приложение не зависит от Refero, Google Fonts или CDN во время работы.

Формат и ключ LocalStorage при редизайне не менялись: существующие задачи продолжают открываться без миграции.

## Возможности

- Добавление кнопкой и по **Enter**, обрезка пробелов, запрет пустого текста, ограничение в 300 символов.
- Выполнение и возврат в активные; статусы сохраняются.
- Удаление с анимацией и отменой в уведомлении. Отмена доступна до 10 секунд; при наведении или фокусе уведомление не исчезает.
- Редактирование: **Enter** / «Сохранить» — применить, **Escape** / «Отмена» — отменить. На мобильном экране не нужна клавиатура для подтверждения.
- Фильтры «Все», «Активные», «Выполненные» и регистронезависимый поиск.
- Компактная статистика, линейный прогресс и очистка только выполненных задач с возможностью отмены.
- Разные пустые состояния для фильтров и поиска. Примеры добавляются только по желанию пользователя.
- Синхронизация открытых вкладок через событие `storage`.
- Справка, управление с клавиатуры, видимый фокус, подписи элементов для скринридеров, поддержка `prefers-reduced-motion`.
- Адаптивная композиция с рабочим блокнотом: две колонки на компьютере, одна на телефоне.

## Технологии

HTML5, CSS3 (Grid, Flexbox, custom properties, media queries), Vanilla JavaScript ES6+, LocalStorage, встроенные SVG-иконки, Web Animations API. Локальные вариативные шрифты Nunito и Caveat с системными запасными шрифтами. Приложение не отправляет запросы в Google Fonts, CDN или аналитические сервисы. Зависимостей npm нет.

## Запуск

### Самый простой способ

Откройте **`index.html` двойным щелчком** в современном браузере. Установка зависимостей и сервер не нужны. Если браузер запрещает LocalStorage для `file://`, приложение сообщит об этом и продолжит работать в памяти вкладки.

### Рекомендуемый вариант для разработки

Откройте папку в VS Code и запустите `index.html` через расширение **Live Server**. Альтернатива, если установлен Python:

```bash
python -m http.server 8080
```

Затем откройте `http://localhost:8080/`.

Для предсказуемого хранения используйте один адрес и порт. `file://`, `localhost:8080`, другой порт и GitHub Pages — разные хранилища. Перенос файлов не переносит задачи.

## Как устроено сохранение

Ключ: **`taskflow.tasks.v1`**. Значение — JSON с версией схемы и массивом задач:

```json
{
  "version": 1,
  "tasks": [
    {
      "id": "уникальный-id",
      "text": "Подготовить проект",
      "completed": false,
      "createdAt": 1794960000000
    }
  ]
}
```

При загрузке приложение читает LocalStorage, проверяет схему и каждую запись. При добавлении, выполнении, редактировании, удалении и отмене удаления весь актуальный массив немедленно записывается обратно. Сохранение не отложено до завершения анимации или закрытия страницы.

### Защита от ошибок

- Нет сохранённых данных → пустой список, без навязанных демонстрационных задач.
- Некорректные записи → восстановление корректных, исключение повторяющихся ID.
- Повреждённый JSON → пустой список и предупреждение.
- Перед дальнейшей записью повреждённые исходные данные копируются в **`taskflow.tasks.recovery`**. Их можно посмотреть в DevTools → Application → Local Storage. Это диагностическая копия, не автоматическая история версий.
- Если резервную копию записать нельзя, запись отключается: исходные данные не затираются.
- Неизвестная версия схемы → запись отключается, чтобы не испортить данные другой версии приложения.
- Хранилище запрещено или переполнено → заметное предупреждение; приложение продолжает работать в памяти. При следующем изменении повторяет попытку записи, кроме случая защитной блокировки из-за неизвестного/повреждённого формата.

**Важно:** LocalStorage не является облачной синхронизацией, резервным копированием или шифрованным хранилищем. Задачи видны пользователям этого профиля браузера. Очистка данных сайта удаляет задачи; приватный режим может удалить их при закрытии. Несколько вкладок обновляют список друг друга, но одновременные конфликтующие изменения не сливаются: действует последняя запись. Разные проекты GitHub Pages на одном домене делят origin; для второго независимого экземпляра смените префикс ключей в `app.js`.

## Архитектура простыми словами

1. **HTML — каркас.** В нём расположены форма, фильтры, статистика, пустое состояние и `<template>` одной строки задачи.
2. **CSS — внешний вид.** Описывает цвета, состояния компонентов, сетку, перестроение на телефоне и анимации. SVG-иконки встроены в страницу и не требуют сети.
3. **JavaScript — поведение.** Объект `state` хранит задачи и временное состояние экрана: фильтр, поиск, редактирование и отмену удаления. Пользовательский текст вставляется через `textContent` и `value`, не через `innerHTML`.
4. **Хранилище — отдельная ответственность.** `loadTasks`, `decodeTasks`, `saveTasks` читают, проверяют и записывают данные. UI не обращается к хранилищу напрямую из каждой кнопки.
5. **Одно направление обновления.** Действие пользователя → изменение `state.tasks` → `saveTasks()` → `render()`. `commit()` объединяет последние два шага. Статистика и прогресс каждый раз вычисляются из массива, а не хранят отдельные потенциально рассинхронизированные значения.
6. **Отрисовка.** `render()` применяет поиск/фильтр, создаёт безопасные строки из шаблона через `DocumentFragment` и обновляет интерфейс. Обработчики строк делегированы списку. Полная перерисовка подходит небольшому личному списку и упрощает код; для десятков тысяч задач стоило бы использовать частичное обновление/виртуализацию.
7. **Удаление.** Сначала удаляется запись и сохраняется новое состояние. Анимируется только временная недоступная для взаимодействия копия строки. Поэтому быстрая перезагрузка или несколько удалений не возвращают задачи.

На собеседовании можно объяснить так:

> «Я разделил проект на разметку, стили и логику. Источник истины — массив задач в памяти. Каждое изменение сразу сохраняется в LocalStorage, после чего интерфейс и статистика строятся заново из этого массива. При старте данные проверяются, ошибки хранения не ломают страницу. Пользовательский текст не интерпретируется как HTML. Фреймворк и backend здесь не нужны: это небольшой локальный продукт».

## Проверки

Сценарии, результаты и ограничения перечислены в [`tests/QA.md`](./tests/QA.md). Повторяемый набор из 18 проверок — [`tests/browser.test.js`](./tests/browser.test.js).

**Не запускайте тесты на адресе с нужными личными задачами:** набор специально добавляет, изменяет и удаляет данные. Используйте отдельный порт или чистый профиль браузера. Откройте приложение на тестовом HTTP-адресе и выполните в DevTools → Console:

```js
const code = await (await fetch('./tests/browser.test.js')).text();
const results = await (0, eval)(code);
console.table(results);
```

`eval` используется только для запуска локального тестового файла в консоли и отсутствует в коде приложения. Для ручной проверки обновите страницу после добавления/выполнения/удаления задачи и сравните состояние до и после.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub, например `taskflow`.
2. Загрузите в корень репозитория `index.html`, `css/`, `js/`, `assets/`, `.nojekyll` и документацию. Не помещайте всё во вторую вложенную папку.
3. Откройте **Settings → Pages**.
4. В **Build and deployment** выберите **Deploy from a branch**.
5. Выберите ветку **main**, каталог **/ (root)** и нажмите **Save**.
6. Дождитесь завершения публикации. Адрес: `https://ВАШ-ЛОГИН.github.io/taskflow/`.
7. Проверьте добавление задачи и перезагрузку уже на опубликованном адресе. Локальные задачи туда автоматически не переносятся.

Все пути относительные (`./css/style.css`, `./js/app.js`, `./assets/favicon.svg`), поэтому приложение работает и в корне домена, и в подпапке. Сборка, GitHub Actions, API-ключи и серверная часть не требуются. Проект подготовлен к публикации, но автоматически никуда не опубликован.

## Границы проекта

Нет аккаунтов, backend, облачной синхронизации, совместного редактирования, сроков, проектов и приоритетов: они не нужны для поставленной задачи. Экспорт/импорт и автоматическое восстановление из диагностической копии не реализованы. Реальные iOS/Android-устройства и другие браузерные движки требуют отдельной проверки; текущий QA выполнен в Chromium.
